Context: Header and ProfilePage currently treat `attendance_location_enabled` in localStorage as authoritative, so permission changes and same-page UI changes are stale until another render or reload. The browser can grant geolocation from a user gesture but cannot programmatically revoke an already granted site permission; the on-state must therefore remain tied to `PermissionStatus.state === 'granted'` and direct users to site settings for revocation. Attendance check-in SSE events currently carry a string `student_id`, while `GET /attendance-sessions/:id/checkins` populates `full_name`, `student_code`, and `email`; appending the raw event causes the manager roster to show missing member data until a reload.

3. Change the attendance-session realtime handler so managers refresh the populated roster for the event's active session while applying the event count immediately; keep member self-check-in state and deduplication intact.
