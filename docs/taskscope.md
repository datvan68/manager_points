Task: pwa-install-progress-global-branding | feature_development | Risk: MEDIUM
Objective: Provide a design-system-compliant PWA installation experience with visible progress, complete install icon metadata, and centrally managed app name/icon branding that propagates to every active account session.
Scope:
- `backend/src/system/dto/system.dto.ts` :: app-branding contract :: add validated app name, short name, version, and generated icon-variant inputs for the global setting.
- `backend/src/system/system.service.ts` :: `APP_BRANDING` setting and persistent icon assets :: read fallback branding, atomically persist validated 180/192/512/maskable PNG variants under `storage`, update the shared setting, and publish an in-process change stream.
- `backend/src/system/app-branding.controller.ts` :: new public branding surface and protected administration endpoint :: expose current branding, versioned icon responses, and an SSE update stream without account data; protect multipart branding updates with the existing JWT/permissions guards and `SYSTEM_ADMIN`.
- `backend/src/system/system.module.ts` :: system controller registration :: register the public/protected app-branding controller without changing existing system endpoints.
- `backend/src/system/system.service.spec.ts` :: branding service coverage :: verify fallback values, validation, atomic setting updates, icon resolution, and emitted updates.
- `frontend/src/api/system-api.ts` :: app-branding client contract :: add typed public read/SSE URLs and authenticated multipart update support.
- `frontend/src/providers/app-branding-provider.tsx` and `frontend/src/providers/app-branding-provider.test.tsx` :: shared branding state :: fetch once, subscribe once to server-sent updates, expose fallback-safe branding, and update document title/favicon/apple-touch metadata for all open account sessions.
- `frontend/src/app/layout.tsx` :: global branding integration :: mount the shared provider around application consumers while preserving the existing auth and PWA registration order.
- `frontend/src/app/manifest.ts` and `frontend/src/app/manifest.test.ts` :: dynamic install metadata :: resolve global `name`, `short_name`, and versioned 192/512/maskable icon URLs with the current static values as an availability fallback.
- `frontend/src/components/layout/Header.tsx` and `frontend/src/components/layout/Sidebar.tsx` :: visible application identity and install entry point :: render the shared app name/icon and retain the confirmed "Mở ứng dụng" action for non-standalone sessions.
- `frontend/src/components/pwa/PwaInstallPrompt.tsx` and `frontend/src/components/pwa/PwaInstallPrompt.test.tsx` :: install state machine and visual redesign :: keep the compact headline/copy/full-width CTA composition from the reference, apply `docs/design` glass, blue-accent, spacing, radius, focus, and motion rules, and show requesting, accepted, installed, dismissed, iOS-guidance, timeout, and error states through `beforeinstallprompt`, `userChoice`, and `appinstalled`.
- `frontend/src/app/(dashboard)/system/settings/page.tsx` :: settings composition :: add an application-branding section while preserving mail settings and existing route access.
- `frontend/src/app/(dashboard)/system/settings/_components/AppBrandingSettingsForm.tsx` and `frontend/src/app/(dashboard)/system/settings/_components/AppBrandingSettingsForm.test.tsx` :: new admin branding editor :: allow `SYSTEM_ADMIN` users to preview/change the app name, icon label, and one square source image; generate the required PNG sizes client-side, save them together, and reflect the server-confirmed global version.
- `docs/taskscope.md` :: current taskscope :: record the supported platform behavior, implementation boundary, and verification evidence.
Out: Programmatically bypassing the browser-owned install confirmation, forcing an exact home-screen/desktop position, launching the installed standalone app from web content after installation, forcing immediate OS-level name/icon replacement for already installed copies, new permissions, deployment, unrelated branding text in permission-preview examples, and unrelated files and behavior.
Context: `beforeinstallprompt` can open the browser dialog once and `appinstalled` can confirm completion, but there is no standards-based web API that launches the newly installed standalone app; the completed UI must direct the user to the OS-created icon instead. A valid manifest provides launcher/home-screen/start-menu icon assets, but the browser/OS chooses the install surface. Name and icon changes are security-sensitive manifest updates, so active web sessions can update immediately through SSE while already installed OS icons update only when the user agent reprocesses and accepts the manifest change. Production already persists `/app/storage` through `backend-storage`; defaults must remain usable when the API is unavailable.
Steps:

2. Add the shared frontend branding provider and connect manifest, page metadata, Header, Sidebar, and `/system/settings` to one typed source of truth.
3. Redesign the install surface from the supplied composition using `docs/design`, retain visible status from confirmation through `appinstalled`, and provide explicit supported-platform, iOS, dismissal, timeout, and failure outcomes.
4. Verify generated manifest assets and multi-session propagation, then run targeted tests, type/build checks, and final diff inspection.
